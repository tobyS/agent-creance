## Executive Summary

The epic is **complete and ready to close.** All five sub-tickets are Done, the
whole substrate is present in the tree (resolver seam, config model, proxy injection
engine, CLI command group, GitHub flagship + docs), and the full hermetic test suite
is green — `make test` (exit 0, all packages incl. the credential ones) plus 148
Python enforcer tests. The commit history (39 commits, `7e3442d`→`35ac097`) is a
clean bottom-up build in the planned a→b→c→d→e order, each sub-ticket a
research/plan/implement/mark-Done unit.

The one thing a reader must understand before closing: the epic's flagship
(AC-0068e) **changed its conclusion, not its capability.** The epic was framed as
"close GH-1 by opening `api.github.com/graphql` with a repo-scoped token." Live
out-of-cage validation proved the mechanism works end-to-end (`POST /graphql → 200`,
token injected, phantom overwritten) but also surfaced a genuine security finding: a
repo-scoped fine-grained PAT bounds *writes* and *private* reads only — public repos
are world-readable, so an opened `/graphql` still lets a prompt-injected agent read
any public repo, which is exactly the ingestion vector the cage exists to close.
Agreed resolution (with the user, documented in the 2026-07-11 note, `docs/design.md`,
and `README.md`): keep the mechanism, but ship **scoped REST** (`/repos/{owner}/{repo}/…`)
as the safe default and treat `/graphql` as a documented opt-in risk rather than
opening it in the shipped config. This is a better outcome than the original framing,
but it means "GH-1 = open `/graphql` safely" is *investigated and deliberately not
shipped as default*, not literally achieved. The capability the epic set out to build
is delivered; the flagship's finding refined how it should be used.

### Code Quality & Integration

The substrate follows the project's seams throughout: `SecretResolver` is a new
`internal/sysdep` interface with `OS*` impl + `sysdeptest` fake (no inline
`os/exec`); the config model adds two flat `Rule` fields + a top-level `credentials:`
block carried through compile/render into `policy.json` with references only (no
resolved value); the proxy resolves host-side at spawn and delivers over inherited
fd 3 (`SpawnWithSecret`); the CLI reuses the existing recompile + hot-reload path.
Nothing bypasses the established abstractions. The Python injector (`inject.py`) ports
the Go value-template as the shared reference spec.

### Test Coverage

Strong and appropriately layered: pure parsing/template rendering table-driven;
policy.json golden; CLI behavior in `.txtar` with stubbed/absent tools; enforcer
request/response hooks in Python unit tests (148 passing); real-tool paths
(op/keychain/mitmdump/GitHub) behind `integration` / `test-enforcer-integration`,
exactly per convention. The secret-hygiene assertions (value never in argv/env/disk/
logs) are encoded in the fakes and resolver tests rather than left to inspection.

### Security Review

This is the epic's core value and it is handled seriously. Overwrite semantics bound
a prompt-injected agent to the injected scope against injected hosts; fail-closed
(472) prevents forwarding unauthenticated or with the phantom; `in-cage` is an honest
lint-able marker for cases injection structurally cannot serve. The 2026-07-11
finding — that URL-layer scoping via a repo-scoped token does not bound *public*
reads — is the most important security outcome of the epic and is now the shipped
default posture (scoped REST), not a footnote. The residual risk (a user who opts
into `/graphql` re-opens public-repo ingestion) is documented prominently.
