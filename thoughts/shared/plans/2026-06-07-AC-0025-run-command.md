# AC-0025 — `run` command (WP-4.4): implementation plan

## Overview

`run` is the headline command. It is **pure orchestration** in `internal/cli`:
prereq check → setup-precondition check → credential check → state resolve →
cache-aware compile → proxy start/attach → cage exec → trapped teardown. Every
heavy piece (lock-file RMW, liveness probe, signal forwarding, compile caching,
`.sb` rendering, Safehouse argv/env) already exists and is unit-tested behind the
`sysdep` seam (see research). The only net-new logic is a small
**setup-precondition check**; everything else is wiring.

Two checkpoint decisions shape this plan:
- **CA detection = keychain query.** `run` verifies the mitmproxy CA by querying
  the login keychain for a certificate named `mitmproxy` (proves `setup` imported
  it), not by file-existence on the auto-generated `~/.mitmproxy/...pem`. This
  needs a new `Keychain.FindCertificate` seam method.
- **Integration smoke deferred.** The real-tool smoke (verification step 3) needs
  a completed `setup` (trusted CA) that doesn't exist yet; it is left to AC-0033
  (the adversarial battery, which already drives `run`) and/or when `setup` lands.
  This plan delivers full unit + hermetic coverage instead.

A note on test placement: `cli.Main()` wires the **real** `OSKeychain`, so a
`testscript` cannot fake the CA-cert or credential lookups. The keychain-dependent
behaviors (happy path, setup-missing, credential-refuse) are therefore covered by
**direct `*App` unit tests with `sysdeptest` fakes** — the project's stated
testability model ("commands take `*App`, not globals — this is what makes them
testable"). `testscript` covers the one cleanly-hermetic ticket scenario
(missing-prerequisite, gated purely by `PATH`).

## Current state

- No `internal/cli/run.go`, no `run*.txtar`, no setup-precondition logic exist.
- `App` (`internal/cli/cli.go:20-40`) has `Commander, Stdout, Stderr, Tested, FS,
  Paths, Clock, HTTP, Keychain, ProcessGroup` — but **not** `Flock`,
  `ProcessManager`, `PortAllocator`, which `proxy.NewManager` requires.
- `Keychain` (`internal/sysdep/keychain.go`) only does `FindGenericPassword`
  (generic-password items); a CA **certificate** needs `find-certificate`.
- All orchestrated packages are implemented and unit-tested (research §"Dependency status").

## Desired end state

`agent-creance run`:
- refuses with the prereq install block + non-zero exit when a tool is missing
  (no stack trace);
- refuses with a clear `Run 'agent-creance setup' first.` pointer + non-zero exit
  when the CA cert isn't in the keychain or the skill file is absent;
- refuses with `cred.Result.Message()` when the Keychain credential is missing/locked/file-based;
- on success, compiles (cache-aware) `policy.json` + always-fresh `network.sb`,
  starts or attaches the refcounted proxy, execs Safehouse with the two
  `--append-profile` fragments + proxy/CA env, blocks while the agent runs,
  forwards SIGINT/SIGTERM to the whole group, and on exit decrements the refcount
  (killing the proxy + purging the overlay only when it's the last agent out).

Verified by: `go build ./...`, `make test` (race) green, `make lint` clean, new
unit tests + `run.txtar` passing.

## Phase 1 — `Keychain.FindCertificate` seam

**Goal:** let `run` cheaply prove the mitmproxy CA is in the login keychain.

### Changes

**`internal/sysdep/keychain.go`**
- Add to the `Keychain` interface:
  ```go
  // FindCertificate reports whether a certificate with the given common name is
  // present in the login keychain, returning its PEM bytes. A missing certificate
  // yields ErrItemNotFound; a locked keychain yields ErrKeychainLocked.
  FindCertificate(commonName string) ([]byte, error)
  ```
- Implement on `OSKeychain`: shell out to `/usr/bin/security find-certificate -c <cn> -p`
  under the same `securityFindTimeout` context + `interpretSecurityErr` mapping as
  `FindGenericPassword` (the `-p` flag prints PEM to stdout). Factor the shared
  run-and-map logic if it reads cleanly; otherwise duplicate the small block.
  - **Verify during implementation:** confirm `find-certificate` returns exit code
    `44` (`errSecItemNotFound`) when absent — it should, but check with the
    integration test below. If it differs, extend `interpretSecurityErr`.

**`internal/sysdep/sysdeptest/keychain.go`**
- Add a `Certs map[string][]byte` field (keyed by common name) + a `WithCertificate(cn, pem string)`
  builder helper, and record `FindCertificate` calls (extend the existing
  `Lookups`/`KeychainQuery` recording, or add a parallel `CertLookups []string`).
- Implement `FindCertificate`: honor `Locked` → `ErrKeychainLocked`; hit in `Certs`
  → return a copy; else `ErrItemNotFound`.

### Tests
- `internal/sysdep/keychain_test.go`: extend the table for `interpretSecurityErr`
  if a new exit code is involved (otherwise unchanged).
- `internal/sysdep/keychain_integration_test.go` (`//go:build integration`): add a
  `FindCertificate` case asserting a known system cert (e.g. an Apple root by CN)
  is found and a bogus CN yields `ErrItemNotFound` — this is where the real exit
  code is confirmed.
- `internal/sysdep/sysdeptest/keychain_test.go`: cover present/absent/locked for the fake.

### Success criteria
- `go build ./...` green; `make test` green; `make lint` clean.
- `FakeKeychain` satisfies the extended interface (compile-time `var _` assertion).

## Phase 2 — `internal/setupcheck` precondition package

**Goal:** the one net-new piece of logic, mirroring `internal/cred`'s shape.

### Changes

**`internal/setupcheck/setupcheck.go`** (new package)
- `const caCommonName = "mitmproxy"` and the skill path
  `~/.claude/skills/agent-creance/SKILL.md` (built from `paths.UserHomeDir`).
- `func Verify(kc sysdep.Keychain, fs sysdep.FileSystem, paths sysdep.PathResolver) (Result, error)`:
  1. `kc.FindCertificate(caCommonName)` — `ErrItemNotFound`/`ErrKeychainLocked` →
     CA-not-trusted; a genuinely unexpected error → return it (non-`OK`, with the
     error so `run` can bail distinctly).
  2. stat the skill file via `fs` — absent → skill-missing.
- `type Result struct { Status Status }` with `Status` constants
  (`StatusOK`, `StatusCANotTrusted`, `StatusSkillMissing`, `StatusKeychainLocked`)
  and `OK() bool`, `Message() string`. `Message()` returns the refuse-and-suggest
  text ending in a clear pointer, e.g.
  `"setup has not been completed (mitmproxy CA not trusted). Run 'agent-creance setup' first."`
  and a locked-keychain variant pointing at unlocking the keychain.
- Decide precedence when both fail (CA first is fine) and document it.

### Tests
- `internal/setupcheck/setupcheck_test.go`: table-driven over
  `FakeKeychain`×`FakeFileSystem` combinations: both present → `OK`; CA absent →
  `StatusCANotTrusted`; skill absent → `StatusSkillMissing`; keychain locked →
  `StatusKeychainLocked`; unexpected keychain error → propagated. Assert
  `Message()` contains `agent-creance setup`.

### Success criteria
- `make test` green; `make lint` clean; `Message()` strings asserted.

## Phase 3 — `run` command + `App` wiring

**Goal:** wire the three missing seams and add the orchestrating command.

### Changes

**`internal/cli/cli.go`**
- Add fields to `App`: `Flock sysdep.Flock`, `ProcessManager sysdep.ProcessManager`,
  `PortAllocator sysdep.PortAllocator` (with doc comments matching the existing
  "for the run command" style).
- In `Main()`, wire `sysdep.OSFlock{}`, `sysdep.OSProcessManager{}`,
  `sysdep.OSPortAllocator{}` (zero-struct impls, confirmed in research).
- In `newRootCmd`, register `root.AddCommand(newRunCmd(app))`.

**`internal/cli/run.go`** (new) — `newRunCmd(app *App) *cobra.Command`,
`Use: "run"`, `Args: cobra.NoArgs` (design lists no flags/args), `RunE` calling a
testable `runRun(ctx, app, dir)` helper. Order of operations:

1. **prereq** — `tools := prereq.DefaultTools(app.Tested)`; `results :=
   prereq.Check(ctx, app.Commander, tools)`. If `prereq.MissingInstructions(results)
   != ""` → print report + instructions to `app.Stdout`, `return fmt.Errorf("%d
   prerequisite(s) missing", …)` (mirror `doctor.go:19-36`). Then emit a single
   loud one-line skew warning to `app.Stderr` for any minor/major mismatch
   (patch stays silent) — reuse whatever `prereq` exposes for classification;
   keep it to one line, never blocks (design:320-333). *(Verify the available
   `prereq` API during implementation; if no helper exists, format inline from the
   results — do not add blocking behavior.)*
2. **setup-precondition** — `res, err := setupcheck.Verify(app.Keychain, app.FS,
   app.Paths)`; on `err` bail; on `!res.OK()` print `res.Message()` to `app.Stdout`
   and `return fmt.Errorf("setup incomplete")` (non-zero, no stack trace).
3. **credential** — `cres, err := cred.Detect(app.Keychain, app.FS, app.Paths)`;
   on `err` bail; on `!cres.OK()` print `cres.Message()` and return non-nil.
4. **state resolve** — `layout, err := state.New(app.Paths).Resolve(dir)`.
5. **compile (policy)** — `c, _ := compile.New(app.FS, app.Paths, app.Clock,
   app.HTTP)`; `polRes, err := c.Compile(ctx, dir)`. Keep `polRes.InputHash`.
6. **config load** — `cfg, err := config.NewLoader(app.FS, app.Paths).Load(
   filepath.Join(dir, ".agent-creance.yaml"))` (needed for `cage.Resolve`).
7. **profile (network.sb)** — `profile.New(app.FS, app.Paths).Compile(dir)`
   (alias the import to avoid the `compile`/`profile` `New` collision).
8. **enforcer extract** — `enforcerPy, err := proxy.NewExtractor(app.FS,
   app.Paths).Extract()`.
9. **proxy attach** — `mgr := proxy.NewManager(app.FS, app.Flock,
   app.ProcessManager, app.PortAllocator, app.Stderr)`; `att, err := mgr.Attach(ctx,
   proxy.StartConfig{Layout: layout, EnforcerPy: enforcerPy, PolicyHash:
   polRes.InputHash, SelfPID: os.Getpid()})`. **Immediately `defer mgr.Detach(layout,
   os.Getpid())`** so every exit path (incl. later errors) decrements — the design's
   "last agent out cleans up" invariant. Capture/join the Detach error.
   - If `att.PortChanged`, the Manager already warned via `app.Stderr`; nothing extra.
10. **cage build** — `b := cage.New(app.FS, app.Paths)`; `in, err := b.Resolve(cfg,
    layout, att.Port)`; `b.Prepare(in)` (writes `proxy.sb` with the live port);
    `inv, err := cage.Build(in)`.
11. **cage run** — `runErr := cage.NewRunner(app.ProcessGroup).Run(ctx, inv)`.
    Blocks until the whole group is reaped; the deferred `Detach` then runs
    **after** `Run` returns (deterministic teardown ordering). Return `runErr`
    (a non-zero agent exit propagates as a non-zero CLI exit).

`dir` is `"."` from `RunE`; the helper takes it as a param for testability.

### Tests

**`internal/cli/run_test.go`** (direct `*App` + `sysdeptest` fakes — fully hermetic):
- **happy path:** construct `App` with all fakes; `FakeKeychain` carrying the CA
  cert + the credential item; skill file + `.agent-creance.yaml` seeded in
  `FakeFileSystem`; `FakePortAllocator` returning a port; `FakeProcessManager` so
  no real `mitmdump`; `FakeProcessGroup` so no real `safehouse`. Assert: exit nil;
  `FakeProcessManager` was asked to spawn `mitmdump` with expected args (proxy
  started); `FakeProcessGroup.Started()` recorded a `safehouse` invocation with the
  two `--append-profile` args (network.sb then proxy.sb) and the proxy/CA env;
  `proxy.lock` shows attach then (last-out) the detach/teardown. This is the
  ticket's "stubs invoked with expected args; lock file shows attach/detach".
- **setup-missing:** `FakeKeychain` without the CA cert → output contains the
  `agent-creance setup` pointer; non-nil error; **no proxy spawned** (assert
  `FakeProcessManager` recorded nothing).
- **credential-refuse:** CA + skill present but no credential item → `cred.Message()`
  surfaced; non-nil error; no proxy spawned.
- **(optional) skill-missing** variant for symmetry.

**`internal/cli/testdata/script/run_missing_prereq.txtar`** (hermetic via PATH):
- `env PATH=$CREANCE_BIN` only (no host tools); `agent-creance run` → `! exec`
  semantics: assert non-zero exit + the refuse-and-suggest install block (model on
  `doctor_missing.txtar`). This reaches only step 1, so it needs no keychain.

### Success criteria
- `go build ./...` green; `make test` (race) green; `make lint` clean.
- Happy-path unit test proves order + stub args + attach/detach; setup-missing and
  credential-refuse prove the no-proxy-started refusals.

## Testing strategy

- **Automated (run after each phase):** `go build ./...` (typecheck), `make test`
  (`go test -race ./...`), `make lint` (`go vet` + `golangci-lint`). `make fmt`
  before committing.
- **Unit:** table tests (Phase 1 fake, Phase 2 setupcheck) and the `*App`-with-fakes
  `run` tests (Phase 3) — the hermetic vehicle for keychain/proxy/cage paths.
- **testscript:** `run_missing_prereq.txtar` for the PATH-gated refusal.
- **Integration (`//go:build integration`):** `FindCertificate` real-keychain case
  (Phase 1). The full real-tool `run` smoke is **deferred** (see Phase 4) — it
  needs a completed `setup`; AC-0033 drives `run` end-to-end and gates M3.

## Manual verification (where feasible without setup)
- `make run ARGS="run"` in a dir with no `.agent-creance.yaml` / no setup → expect a
  clean refuse-and-suggest (prereq or setup pointer), never a stack trace.

## Risks / notes
- **`find-certificate` exit code** for absent certs is assumed `44`; the Phase 1
  integration test confirms it — adjust `interpretSecurityErr` if it differs.
- **Keychain presence ≠ trust.** A keychain query proves `setup` imported the CA,
  not that the trust dialog was confirmed (the `add-trusted-cert`-returns-0-on-cancel
  hazard, design:443). That robust live-curl verification stays `setup`/`doctor`'s
  job by design; `run`'s check is intentionally the cheap one.
- **`compile`/`profile` import collision:** both expose `New`; alias one.
- Keep all OS access behind the seams already on `App`; do not add inline
  `os/exec`/keychain calls in `run.go`.
