# Research: AC-0025 — `run` command (WP-4.4)

## Research question

How do we implement `agent-creance run` — the headline command that ties together
prereq check → setup-precondition check → state resolve → cache-aware compile →
proxy start/attach → cage exec → trapped teardown, failing with a clear pointer
(not a stack trace) when setup is missing? What exact APIs does it orchestrate,
what patterns must it follow, and what is genuinely undecided?

## Summary

Every building block `run` needs already exists and is unit-tested behind the
`sysdep` seam. `run` is **pure orchestration in `internal/cli`** — it must not
reimplement any lock-file RMW, liveness probe, signal forwarding, or compile
caching; those live in `internal/proxy`, `internal/cage`, and
`internal/policy/compile` respectively. The work is: a new `internal/cli/run.go`
command constructor, wiring three not-yet-present `sysdep` seams onto `App`
(`Flock`, `ProcessManager`, `PortAllocator` — needed by `proxy.NewManager`), a
small **setup-precondition check** (the only net-new logic), and a hermetic
`run.txtar` testscript that stubs `safehouse` + `mitmdump`.

The one genuinely open decision is **how `run` cheaply detects "trusted CA"**,
because the `setup` command that establishes CA trust (AC-0026) is not built yet,
so the on-disk contract for "setup ran" is not yet defined.

## The 7-step pipeline (authoritative ordering)

From the spec (`thoughts/shared/discussions/2026-06-04-v0.1-technical-specification.md:280-286`)
and design (`docs/design.md:361-364`, `:387`):

1. **prereq check** — tools installed + version skew (reuse `internal/prereq`)
2. **setup-precondition check** — trusted CA + skill present, else point at `setup`
3. **state resolve** — canonical path → identity hash → out-of-tree state layout
4. **compile (cache-aware)** — `policy.json` via input-hash cache; `network.sb` always regenerated
5. **proxy start/attach** — refcounted lifecycle (flock-guarded)
6. **cage exec** — Safehouse invocation with env + two `--append-profile` fragments
7. **trapped teardown** — wait-for-group → refcount decrement → kill proxy iff last out

Key ordering invariant (`docs/design.md:404`, `:406`): the runner waits for the
**whole process group to exit before** the lock-file decrement, so teardown is
deterministic. Clean exit, SIGINT, and crash all hit the same teardown path.

## Exact APIs `run` orchestrates

All constructors take `sysdep` seams already (mostly) on `App`. Signatures verified
against the source:

### State — `internal/state/state.go`
- `state.New(paths sysdep.PathResolver) *Resolver` (`:65`)
- `(*Resolver).Resolve(dir string) (Layout, error)` (`:84`) — abs+symlink-resolve, identity hash. Existing call site: `logs.go:31` uses `state.New(app.Paths).Resolve(".")`.
- `Layout` accessors (`:177-206`): `PolicyJSON()`, `NetworkSB()`, `ProxyProfileSB()` (=`proxy.sb`), `ProxyLock()`, `EgressJSONL()`, `ClaudeConfigDir()`, `SessionOverlay()`. Fields: `Canonical`, `Hash`, `Root`. **No artifact I/O** — only computes paths.

### Config — `internal/config/load.go`, `config.go`
- `config.NewLoader(fs, paths) *Loader` (`load.go:39`); `(*Loader).Load(projectPath string) (*Config, error)` (`:48`). `projectPath` is the **config file path** (`filepath.Join(dir, ".agent-creance.yaml")`); merges implicit global + project, resolves includes.
- `Config` (`config.go:29-35`): `Agent{Command []string, Workdir string}`, `Safehouse{AddDirsRW/RO, Enable}`, `Network{HostServices []HostService{Label,Port}, Egress}`, `Env map[string]string`.
- Note: `compile.Compile` already loads config internally; `run` still needs `*Config` separately to feed `cage.Builder.Resolve`.

### Credentials — `internal/cred/cred.go`
- `cred.Detect(kc sysdep.Keychain, fs sysdep.FileSystem, paths sysdep.PathResolver) (Result, error)` (`:103`) — package function, no struct.
- `Result.OK() bool` (`:67`), `Result.Message() string` (`:72`) — ready-made refusal strings.
- `Status` constants (`:45-59`): `StatusOK`, `StatusLocked`, `StatusFileFallback` (file-based `~/.claude/.credentials.json` → refuse, v0.1 unsupported per `design.md:437`), `StatusMissing`.

### Policy compile — `internal/policy/compile/compile.go`
- `compile.New(fs, paths, clock, http) (*Compiler, error)` (`:108`)
- `(*Compiler).Compile(ctx, projectDir string) (Result, error)` (`:232`)
- `Result` (`:134-140`): `PolicyPath`, `InputHash` (**the `PolicyHash` to feed the proxy**), `Skipped` (cache hit), `AllowCount`, `DenyCount`. Writes `policy.json` atomically out-of-tree; cache hit leaves file+mtime untouched (`:240-249`).
- Mirror the existing pattern in `policy.go:137-155` (`resolvePolicy`).

### Profile (.sb) — `internal/profile/compile.go`, `profile.go`
- `profile.New(fs, paths) *Compiler` (`compile.go:33`); `(*Compiler).Compile(projectDir string) (Result, error)` (`:52`) → writes `network.sb` atomically, **no cache, rewritten every launch**. `Result{ProfilePath, AllowCount}`.
- The launch-time proxy-port fragment is **not** written here — `cage.Builder.Prepare` writes it to `Layout.ProxyProfileSB()` via `profile.RenderProxyFragment(port)`.
- Import collision caution: `compile.New` (4-arg) vs `profile.New` (2-arg) — alias one import.

### Proxy lifecycle — `internal/proxy/lifecycle.go`, `extract.go`
- `proxy.NewExtractor(fs, paths) *Extractor` (`extract.go:57`); `(*Extractor).Extract() (string, error)` (`:68`) → writes embedded enforcer addon, returns `enforcer.py` path. Idempotent; call every run.
- `proxy.NewManager(fs sysdep.FileSystem, lock sysdep.Flock, proc sysdep.ProcessManager, ports sysdep.PortAllocator, warn io.Writer) *Manager` (`:60`) — **`warn` = `app.Stderr`**.
- `(*Manager).Attach(ctx, cfg StartConfig) (Attachment, error)` (`:96`).
  - `StartConfig{Layout, EnforcerPy, PolicyHash, SelfPID}` (`:65-75`).
  - `Attachment{Port, ProxyPID, PortChanged}` (`:78-87`) — `Port` is what the cage points at; `PortChanged==true` means a crash restart got a new port and already-attached agents were warned.
- `(*Manager).Detach(layout state.Layout, selfPID int) error` (`:152`) — removes PID under flock; if last out, `SIGTERM`s the proxy (`:168`) and purges the session overlay (`:172`). **No separate kill call** — last-out teardown is automatic inside `Detach`.
- Launches `mitmdump` (`lifecycle.go:29`) — **binary name `mitmdump`, not `mitmproxy`** (matters for the testscript stub).

### Cage — `internal/cage/cage.go`, `run.go`
- `cage.New(fs, paths) *Builder` (`cage.go:123`).
- `(*Builder).Resolve(cfg *config.Config, layout state.Layout, port int) (Inputs, error)` (`:130`) — computes `CACertPath = ~/.mitmproxy/mitmproxy-ca-cert.pem` and `HomeDir`.
- `(*Builder).Prepare(in Inputs) error` (`:163`) — seeds ephemeral `CLAUDE_CONFIG_DIR/settings.json` (if absent) and **(re)writes the proxy-port `.sb` fragment** to `Layout.ProxyProfileSB()`. Does **not** write `network.sb`.
- `cage.Build(in Inputs) (Invocation, error)` (`:69`) — pure; emits two `--append-profile` flags in order (`NetworkSB()` then `ProxyProfileSB()`), `--env-pass`, `--`, agent command. All proxy/CA env vars computed internally from `ProxyPort`+`CACertPath`.
- `Invocation{Path("safehouse"), Args, Env}`; `cage.Binary = "safehouse"` (`:38`).
- `cage.NewRunner(pg sysdep.ProcessGroup, opts ...Option) *Runner` (`run.go:41`); `WithGrace(d)` (`:35`); `(*Runner).Run(ctx, inv) error` (`:53`) — forwards SIGINT/SIGTERM to the group, 5s grace then SIGKILL, returns the child's exit error **only after the whole group is reaped**. So `Detach` must be called strictly after `Run` returns.

### Suggested orchestration order (composed from the contracts)
1. `prereq.Check` (step 1) → refuse if missing tools (mirror `doctor.go:19-36`)
2. setup-precondition check (step 2) → refuse + point at `setup`
3. `layout := state.New(app.Paths).Resolve(dir)`
4. `cfg := config.NewLoader(...).Load(dir+"/.agent-creance.yaml")`
5. `cred.Detect(...)` → refuse on `!OK()` with `Message()`
6. `enforcerPy := proxy.NewExtractor(...).Extract()`
7. `polRes := compile.New(...).Compile(ctx, dir)` → `polRes.InputHash`
8. `profile.New(...).Compile(dir)` → `network.sb`
9. `att := mgr.Attach(ctx, StartConfig{Layout, EnforcerPy: enforcerPy, PolicyHash: polRes.InputHash, SelfPID: os.Getpid()})`
10. `b := cage.New(...); in := b.Resolve(cfg, layout, att.Port); b.Prepare(in); inv := cage.Build(in)`
11. `runErr := cage.NewRunner(app.ProcessGroup).Run(ctx, inv)` (blocks)
12. `mgr.Detach(layout, os.Getpid())` — **deferred**, runs strictly after step 11

## CLI conventions to follow (`internal/cli`)

- Command shape: `newRunCmd(app *App) *cobra.Command` with `RunE`, registered in `newRootCmd` via `root.AddCommand(newRunCmd(app))` (`cli.go:60-63`). Design lists **no flags/args** for `run` (`design.md:361-364`) → `Args: cobra.NoArgs`.
- `App` (`cli.go:20-40`) already has: `Commander, Stdout, Stderr, Tested, FS, Paths, Clock, HTTP, Keychain, ProcessGroup`. Comments at `cli.go:32-39` note `Keychain`/`ProcessGroup` were added "for the run command".
- **Gap:** `proxy.NewManager` needs `sysdep.Flock`, `sysdep.ProcessManager`, `sysdep.PortAllocator` — **none are on `App`** (`cli.go:20-40`) nor wired in `Main()` (`cli.go:72-83`). They must be added (mirroring how `ProcessGroup`/`OSProcessGroup{}` was added) and the OS impls wired in `Main()`.
- Non-zero exit with a clean message: no sentinel error / no special exit codes. `newRootCmd` sets `SilenceErrors:true` + `SilenceUsage:true` (`cli.go:53-54`); `Main` renders `error: <msg>` to stderr + exit 1 (`cli.go:85-88`). The refuse-and-suggest pattern (`doctor.go:30-33`): print the human-readable block to `app.Stdout`, then `return fmt.Errorf(...)` with a short summary.
- Version skew on `run`: **never blocks**; patch skew silent, minor/major a single loud line, then proceeds (`design.md:320-333`). Only a *missing* tool is a hard failure.

## testscript harness (`internal/cli/script_test.go`)

- `TestMain` maps `"agent-creance" → cli.Main` (`:26-30`); `Setup` exports `$CREANCE_BIN` = the dir holding the in-process CLI (`:38-52`). `Cmds` registers custom commands like `seedaudit` (`:36-37`, impl `:63-95`) which reproduces the out-of-tree `state.New(paths).Resolve(".")` layout to seed files into the same `Layout.Root` the CLI computes.
- A `run.txtar` must: set `env HOME`/`XDG_CACHE_HOME` under `$WORK` (hermetic, offline compile — pattern from `policy_show.txtar:7-8`), set `PATH` to a fake-tools dir **followed by** `$CREANCE_BIN`, drop fake **`safehouse`** and **`mitmdump`** executables via `-- bin/safehouse --` file blocks (chmod'd exec), supply `-- .agent-creance.yaml --`, then assert stdout/stderr/exit (`!` prefix = non-zero, `policy_show.txtar:16`, `doctor_missing.txtar:10`).
- Existing scripts: `version`, `doctor_missing/healthy`, `policy_show/explain/no_config/refresh`, `logs`, `logs_summary`. No `run*.txtar` yet.
- To pre-seed `proxy.lock`/`policy.json` for attach-path tests, copy the `seedAudit` layout-resolution approach.

## The setup-precondition check (the one net-new piece)

What "present" means:
- **Skill present** (`design.md:284`): `~/.claude/skills/agent-creance/SKILL.md` exists — clean signal, only `setup` creates it. Cheap file-exists via `app.FS`.
- **Trusted CA** (`design.md:426`, `:443`): the mitmproxy CA in `~/.mitmproxy/` is installed into the login keychain by `setup` (one sudo). The **robust** verification (spawn mitmproxy, curl `https://example.com`, validate chain) is deliberately reserved for `setup`/`doctor` (`design.md:443`); `run`'s check must be **cheap** (`design.md:362-364` just says "no trusted CA").

The subtlety: `~/.mitmproxy/mitmproxy-ca-cert.pem` is auto-generated by mitmproxy's
**first ever run** (`design.md:426`), so its mere existence does **not** prove
`setup` trusted it. A pure file-exists check on that path is the documented cheap
signal but is weak. Stronger-but-still-cheap options (keychain query; a marker
file `setup` writes) require defining a contract that AC-0026 (`setup`) must honor
— and AC-0026 is **not built yet** (this ticket does not depend on it; M3 is only
reached "once AC-0026 is also in place", `AC-0025:49`). `doctor.go` explicitly
defers CA-trust checking to future work. **This is the open question below.**
